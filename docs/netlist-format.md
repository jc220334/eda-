# 网表格式设计（v1）

本文定义课程 PCB 编辑器使用的基础网表格式。目标是先完成“逻辑设计到 PCB 网络”的可靠导入，不追求兼容商业 EDA 软件的全部语法。

## 1. 设计目标

- 格式清晰，能够用文本编辑器直接检查和修改。
- 只描述逻辑元件、封装引用和电气连接，不包含画布坐标。
- 支持元件位号、任意字符串引脚编号和多引脚网络。
- 能够在导入前完成完整校验，避免只导入一半后留下损坏工程。
- 为后续飞线生成、布局、布线和电气连接检查提供稳定输入。
- 第一版可以转换为其他格式，但不会把第三方格式解析细节直接写进 PCB 模型。

## 2. 现有格式调研与选择

| 格式类型 | 优点 | 本项目中的限制 |
| --- | --- | --- |
| SPICE 网表 | 文本简单，适合电路仿真 | 主要描述器件和节点，不直接表达 PCB 封装引用、位号更新和层信息 |
| KiCad 网表 | 面向 PCB，字段完整，行业认可度高 | S 表达式和组件结构较复杂，第一版解析成本较高 |
| EDIF | 标准化程度高，适合工具交换 | 结构庞大，课程项目难以在短期完整支持 |
| CSV | 易于编辑和程序读取 | 难以表达嵌套对象、版本和可选字段，错误定位能力弱 |
| 自定义 JSON | 可读、可做 Schema 校验、便于扩展和测试 | 不与商业 EDA 格式直接兼容，需要单独编写适配器 |

第一版选择自定义 JSON。它最适合三人小组快速完成可验证的导入流程，也能明确教学重点：元件、封装、引脚和网络之间的关系。

KiCad、SPICE 或 EDIF 兼容性作为后续适配层处理。核心 PCB 模型不依赖任何第三方网表的内部写法，避免解析器细节污染板级数据。

## 3. 文件约定

- 推荐扩展名：`.net.json`
- 编码：UTF-8
- 根对象格式名：`eda-course-netlist`
- 当前版本：`1`
- JSON 中不允许注释和尾随逗号。
- 文件名只用于标识，网表中的元件顺序不决定导入顺序。

正式 JSON Schema 位于 [`schemas/netlist.schema.json`](../schemas/netlist.schema.json)。

## 4. 基本结构

```json
{
  "format": "eda-course-netlist",
  "version": 1,
  "components": [
    {
      "ref": "U1",
      "footprint": "SOIC-8_3.9x4.9mm_P1.27mm",
      "value": "74HC00"
    }
  ],
  "nets": [
    {
      "name": "VCC",
      "connections": [
        { "ref": "U1", "pin": "8" }
      ]
    }
  ]
}
```

### 4.1 根对象

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `format` | string | 是 | 固定为 `eda-course-netlist` |
| `version` | integer | 是 | 当前固定为 `1` |
| `components` | array | 是 | 元件声明列表，至少包含一项 |
| `nets` | array | 是 | 网络列表，至少包含一项 |

### 4.2 元件

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ref` | string | 是 | 唯一元件位号，例如 `U1`、`R10` |
| `footprint` | string | 是 | 元件库中的封装 ID，不包含库文件路径 |
| `value` | string | 否 | 逻辑值或器件型号，用于显示，不参与封装匹配 |

`ref` 在清洗首尾空白后按 ASCII 大写比较，例如 `u1` 和 `U1` 视为相同位号并判定为重复。写入 PCB 后使用标准大写形式。

### 4.3 网络与连接

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 唯一网络名称，例如 `VCC`、`SIG_A` |
| `connections` | array | 是 | 至少两项连接；每个连接表示一个元件引脚 |

连接对象：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ref` | string | 是 | 已声明的元件位号 |
| `pin` | string | 是 | 对应封装中的电气引脚编号，例如 `1` 或 `A3` |

引脚编号使用字符串，不使用整数。这样可以支持 `A1`、`B12` 等封装引脚，也能保留 `01` 和 `1` 的区别。匹配时清洗首尾空白并按 ASCII 大写比较。

一个引脚如果希望保持未连接，可以不出现在任何网络中。不得使用空网络或只含一个引脚的网络表达未连接状态。

## 5. 数据边界

网表只提供：

- 有哪些元件。
- 每个元件使用哪个封装。
- 哪些元件引脚属于同一个网络。

网表不提供：

- 元件在 PCB 中的坐标。
- 元件旋转角度和所在面。
- 板框尺寸。
- 层组和走线。
- 封装的焊盘几何。

以上内容由元件库和 PCB 工程文件分别保存。

## 6. 导入流程

导入必须是原子操作。所有阻塞错误处理完成后才修改 PCB 工程；失败时保留导入前状态。

1. 读取文件并解析 JSON。
2. 按 Schema 校验基本结构。
3. 建立规范化位号索引，检查重复位号。
4. 建立规范化网络索引，检查重复网络名称。
5. 对每个元件解析封装 ID，并从元件库查找封装。
6. 对每个网络连接检查元件是否存在。
7. 检查封装中是否存在该电气引脚。
8. 检查一个引脚是否出现在多个网络中。
9. 将连接转换为“元件实例 ID + 引脚编号 + 网络 ID”。
10. 生成网络对象和未连接焊盘之间的飞线。
11. 统一提交元件、网络和连接关系。

如果是新建 PCB，元件位置可以由导入器按网格临时摆放；如果是已有 PCB，后续版本再增加增量更新模式。v1 先采用“全新 PCB 导入”语义。

## 7. 规范化规则

- 位号：去除首尾空白，ASCII 大写。
- 引脚编号：去除首尾空白，ASCII 大写。
- 封装 ID：去除首尾空白，大小写敏感。
- 网络名称：去除首尾空白，保留原有大小写。
- 所有字符串必须是有效 UTF-8。
- 空字符串视为校验错误。

不要在解析阶段静默纠正拼写错误。程序只能规范化允许的大小写和空白，不能猜测不存在的封装或引脚。

## 8. 错误诊断

| 错误码 | 含义 | 阻断导入 |
| --- | --- | --- |
| `NET-001` | JSON 语法错误 | 是 |
| `NET-002` | 根格式或版本不支持 | 是 |
| `NET-003` | 必填字段缺失或类型错误 | 是 |
| `NET-004` | 元件位号为空或重复 | 是 |
| `NET-005` | 网络名称为空或重复 | 是 |
| `NET-006` | 网络包含少于两个连接 | 是 |
| `NET-007` | 引用未声明的元件 | 是 |
| `NET-008` | 元件库中找不到封装 | 是 |
| `NET-009` | 封装中找不到对应引脚 | 是 |
| `NET-010` | 同一引脚出现在多个网络中 | 是 |
| `NET-011` | 同一网络包含完全重复的连接 | 是 |

每条诊断至少包含：

- 错误码
- 面向用户的错误信息
- JSON 路径，例如 `components[2].footprint`
- 相关元件位号和引脚编号（如果存在）

## 9. 导入结果

建议导入服务返回以下结果，不直接操作窗口：

```text
ImportResult
├── success
├── diagnostics[]
├── componentCount
├── matchedPinCount
├── netCount
└── ratsnestEdgeCount
```

界面只负责选择文件、显示诊断和确认是否创建 PCB。网表解析、匹配和网络构建属于 PCB 业务模块，由成员 C 负责。

## 10. 引脚和多焊盘关系

一个电气引脚可能对应多个焊盘，例如散热焊盘由多个铜区共同组成。网表连接到的是“引脚编号”，PCB 模型需要在引脚匹配后返回全部关联焊盘：

```text
FootprintPin 1 -> Pad A, Pad B, Pad C
```

网络和参考点不要在元件库的原始焊盘上直接写入。元件库是共享只读模板，网络只存在于具体的 PCB 元件实例中。
